RADIUM V50 – MATCH FLOW + TV DISPLAY FIXES

1. Match Flow persistence
- SAVE MATCH FLOW now writes directly through radium_save_tournament and reads the setting back from Supabase.
- The UI reports success only after Supabase read-back confirms the exact selected flow.

2. Match Queue ordering
- Ready Combative matches are ordered using the saved Match Flow.
- Round-by-round and Boys/Girls-first modes use one ordering rule shared by the queue.

3. TV Display
- TV reads the saved Match Flow from tournaments.settings.setup.matchFlow.
- Upcoming TV matches follow the same ordering as Match Queue.
- For a one-court tournament, only Court 1 is displayed.
- Ticker is slowed for readability and follows the same Match Flow ordering.
- Completed matches include winner_player_id in the TV query.
- A winner announcement is shown only from the actual recorded winner_player_id.
- A short animated transition is shown when a new live match appears.
- No winner is inferred from seed order, score display order, or the next match.

4. Existing bracket/gameplay data is not regenerated by these changes.
5. ANYO ordering/scoring logic is not changed by the TV/Combative Match Flow work.
